One-Line Thesis

Treat agent interaction traces as managed data assets — persistent, queryable, versioned — not transient stdout deleted after each rollout.

ELI5 positioning: Claw-R1 is the plumbing between agents and RL trainers. It does not invent a new policy gradient — it makes every LLM call a first-class data record you can filter, label, and feed into any training backend.

The Problem · ELI5

10,000 Agents, Millions of Steps — Then Deleted一万 Agent、百万 Step — 然后删除

Agent RL is becoming a data engineering problem. Today's systems treat interaction traces like terminal stdout.Agent RL 正在成为数据工程问题；现有系统把交互轨迹当终端 stdout

2 / 5
Imagine a factory where 10,000 workers each take millions of actions per day — and at shift end, every record is shredded. No search, no replay of the one bad step, no version history. That is how most agent RL pipelines treat interaction data today.

Before — Ephemeral Logs

  • Agent → LLM direct; stdout-style traces
  • Whole trajectories only; no step query
  • Rewards & tool calls lost or buried
  • No versioning, filtering, or curation
  • Training re-runs from scratch each time

Result: credit assignment blind; failure steps unrecoverable

→

After — Managed Data Assets

  • Agent → Gateway → LLM; every step recorded
  • Step records: prompt_id, response_id, reward, tool
  • Data Pool: filter, version, quality labels
  • SQL-like queries on failure patterns
  • TrainingBackend serves curated batches

Result: train only what failed; data compounds over time

Scale Pain

OpenClaw-class deployments → heterogeneous agents, multi-turn tool loops, millions of steps. Without middleware, you cannot inspect, curate, or selectively train on the 1 wrong step in a 20-step trajectory.

Reframe

Agent RL = data engineering problem. Policy algorithms (GRPO, PPO, DPO) matter — but only after you have queryable, versioned, step-level interaction data. Claw-R1 owns that lifecycle.

Gateway — Unified Capture

All agent requests pass through one API surface. Automatically records prompt, response, reward signals, tool calls, and metadata — without modifying agent logic for black-box deployments (point base_url at Gateway).

Data Pool — Replay Buffer++

Step → metadata → filtering → versioning → quality labels → training-ready batches. Multi-dimensional rewards (rule / discriminative RM / generative RM), human feedback, policy version tracking, train/val channel isolation.

White-Box

Agent submits steps via API; full state visibility for debugging and curation.

Black-Box

Existing agents redirect LLM endpoint to Gateway — zero code change to capture traces.

Algorithm-Agnostic

Claw-R1 prepares data; trainer selects steps → batches → any downstream RL algorithm.

Why Step-Level?

Train Only the Wrong Step只训练错误的那一步

Trajectory-level storage loses granularity. Step-level records enable surgical credit assignment and queryable failure mining.轨迹级存储丢失粒度；Step 级记录支持精准 credit assignment 与可查询失败挖掘

Data Pool as Replay Buffer++

Traditional replay buffers store whole trajectories. Claw-R1 adds:

  • Per-step metadata & multi-dimensional rewards
  • Policy version tracking (freshness-aware curation)
  • Human feedback integration
  • Channel-based train/val isolation
  • Pluggable TrainingBackend export

Query Example — SQL-Like Failure Mining

SELECT * FROM step_pool
WHERE reward < 0
  AND tool = 'browser'
  AND action LIKE '%search%'
  AND policy_version >= 'v2.1'
ORDER BY timestamp DESC
LIMIT 500;

Natural language equivalent: "Show all failed search steps where reward < 0 and tool = browser"

Analogy — Feature Store

Like recommendation-system feature stores: curated, versioned, queryable inputs for downstream models — but for LLM agent steps (state, action, reward, tool metadata).

Analogy — Data Lake

Like analytics data lakes: ingest heterogeneous sources, partition by channel/quality, serve filtered slices to consumers — here the consumer is an RL trainer, not a BI dashboard.

Key Takeaways

  • Data first: agent RL fails without managed step traces
  • Middleware, not algorithm: works with GRPO, PPO, DPO, or custom trainers
  • Complements SkillRL: Claw-R1 supplies fuel; SkillRL compresses + optimizes
  • Inspectable: demo UI for live trajectory curation by quality & readiness
  • Heterogeneous: white-box + black-box agents through one Gateway
