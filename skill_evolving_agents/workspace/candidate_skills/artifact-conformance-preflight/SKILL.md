description: Run equality, range, calibration, graph, companion, and geometry conformance gates. Independently recompute source-scene primitive assembly and world transforms, compare every exported mesh's placement and shape, and fail transform and assembly defects that exporter-derived checks miss. Require a task-derived acceptance tolerance and independent-oracle evidence as preflight inputs; fail closed when either is absent and report each failing mesh path, observed Chamfer, threshold, attribution. Use when deliverables have checkable rules, confidence separates by evidence, a graph needs reachability or edge-target checks, part or link meshes are exported from a Three.js source scene, CAD file, OBJ, or GLB, a companion visualization must be checked, a local geometry gate reports clean while an objective or external mesh check reports a chamfer, placement, hierarchy, or transform mismatch, or the expected mesh would be rebuilt by the same primitive, transform, or exporter path that produced the artifact.

## Overview

Turn the task-visible acceptance contract into a machine-checkable JSON spec, then validate the complete artifact before packaging. The preflight covers ten invariant classes: `equality`, `numeric_range` after unit conversion, `calibration` across evidence-strength groups, `independent_recompute` for derived values without a stated expected result, `field_encoding` for declared null, absence, and forbidden sentinels, `structural` for composite objects such as pivot tables, `domain_membership` for categorical allowed sets, `graph_structure` for graphs, `companion_artifact` for every additional named deliverable, and `geometry_conformance` against an independently derived source-scene surface.

`geometry_conformance` is an executed gate, not a documentation claim. The expected surface must be derived independently from the task source scene and the task-derived spec, then compared with every part mesh and link mesh over the complete artifact. The producer's own reconstruction, `exact_union=True`, exact per-mesh vertex or triangle equality, matching vertex or triangle totals, file or mesh counts, and an inline `ALL CHECKS PASSED` report are inadmissible as equivalence evidence: they can all be self-consistent while the exported geometry is displaced. Only a separately implemented source reader and surface builder at the task-stated tolerance can pass the gate.

Counts and degenerate-face checks establish structural validity only. An expected value or mesh produced by the same transformation or exporter path as the artifact is not independent evidence. Without a separately implemented task-derived path, record the invariant as unverifiable and block submission rather than fabricating an expected value. This local, task-derived check is not the hidden verifier; a structural pass proves only declared shape, domain, graph, and encoding.

## When to Use

Use this skill when any one of these is enough:

- The task states machine-checkable constraints: exact values, numeric bounds, units, or confidence that must separate by evidence strength.
- A structural suite passes but a content, numeric, or calibration contract is unchecked; a derived value lacks an independent oracle; or a field may still use a placeholder or sentinel.
- The deliverable is a workbook or report with pivot tables, grouping keys, or categorical values whose allowed set, fields, aggregation mode, or cache the task states.
- A task exports 3D meshes or other geometric artifacts from a source scene, CAD file, or Three.js object, and acceptance depends on the exported shape matching the source within a stated tolerance.
- An exported mesh's placement, primitive assembly, hierarchy, or transforms may be wrong even when a same-path local parse-and-export gate reports clean, including Three.js scenes exported to OBJ or GLB.
- A local geometry gate, structural suite, or producer's exporter check reports clean while an objective or external mesh check still reports a chamfer, placement, hierarchy, or transform mismatch.
- The expected mesh would be reconstructed by the same primitive decomposition, expected coordinates, or transform or exporter code path that produced the artifact, so a numerically matching comparison may still be self-referential.
- The task names a companion deliverable such as a flowchart image, DOT graph, SVG, or HTML report beside a JSON artifact, and its legend, shapes, styles, or annotations must encode declared distinctions.

## Do Not Use

Do not use when the deliverable has no machine-checkable contract, the artifact is unavailable in full, or expected values cannot be derived without guessing. Do not invent ground truth, relax a threshold, replace the hidden verifier, or check a sample and call the artifact conformant. `geometry_conformance` is not aesthetic judgment; without task-visible source geometry or tolerance, report it unverifiable rather than guessing or accepting any mesh that opens.

## Workflow

1. **Extract the contract.** Read the task and every acceptance rule. Record each rule as data in a versioned JSON spec: invariant id/class, field path, locator, rule, bounds, unit conversion, calibration groups/separation, tolerance, expected source, nullability, required presence, forbidden sentinels. Record geometry tolerance as `acceptance_tolerance` only from a task-stated value; a local default or looser tool tolerance is not the contract, and no stated value leaves geometry unverifiable. Never encode expected values here or in the validator.
2. **Inventory every deliverable and mesh.** List the primary artifact, graphs, workbooks, companions, and every exported part and link mesh with path. Nested paths count separately. Require one constraint group per deliverable and one `geometry_conformance` entry per mesh; a declared mesh with no geometry invariant is an incomplete inventory.
3. **Declare composite, graph, and companion structure.** Record a pivot's collection path, locator, required fields, non-empty row/column/value lists, aggregation field and modes, and cache field. Record a graph's path, node collection/id, edge collection/source/target, entry node, and terminal exception; record each categorical field's task-declared allowed set. For rendered output, record path, format, node collection/type field, and a type-to-shape, style, class, or annotation mapping from a task-visible legend or style table, never the rendered file. A rule not stated by the task is unverifiable.
4. **Choose the invariant adapter.** Map the contract using the keys in `references/invariant-spec.md`. Use `unverifiable` when provenance, a graph endpoint, a domain rule, a rendering convention, a source shape, or a tolerance cannot be established.
5. **Select an independent oracle.** A second implementation must use different intermediate operations than the producer. Metamorphic relations assert positivity, plausible bounds, agreement under a recorded factor and offset, or reversibility; record the oracle module and inputs, or every relation and parameter. Never substitute the producer's code, intermediates, or output. For geometry, reconstruct from source primitive parameters through a second path free of the producer's primitive decomposition, expected coordinates, or transform code, and record `reader`, `transform_path`, and independence evidence in the spec and report.
6. **Recompute primitive assembly and world transforms.** Read the task source scene directly, including primitive ids, types, dimensions, local transforms, and parent chain. Rebuild membership and world transforms through a math path separate from the parse-and-export implementation under test; compare exported vertex positions, bounds, placement, and triangle counts. Run `scripts/independent_mesh_oracle.py SOURCE_SCENE ARTIFACT --spec TOLERANCE_SPEC` per artifact or root; fail omitted, duplicated, mis-parented, or wrongly translated, rotated, or scaled primitives.
7. **Run the whole-artifact preflight.** Execute `scripts/preflight.py` on the full JSON, JSON Lines, or artifact root, never a sample; pass `--artifact-root` when paths anchor to a directory. It emits one structured violation per failing object and rule with class, locator, field, observed, expected, and diagnosis. A companion path must exist and parse before each node type is compared with its encoding.
8. **Trace and repair non-geometry failures.** Find the producing step. Repair normalization for `field_encoding`, pivot or category mapping for `structural` and `domain_membership`, graph assembly, and rendering template. Rebuild and rerun the same spec until those checks exit zero.
9. **Run the mandatory pre-submit geometry gate.** Enumerate every part and link mesh, derive the expected surface independently from the source scene and spec per `references/mesh-geometry-conformance.md`, and run both `scripts/independent_mesh_oracle.py` for assembly/transform defects and `scripts/preflight.py` with the geometry spec over the complete artifact. Use the spec's task-derived `acceptance_tolerance`, never a local or looser `tolerance`; no stated task tolerance means unverifiable. Stop before packaging on any mesh above tolerance, naming path, observed distance, threshold, and placement, transform, assembly, or shape attribution. Record provenance, independence evidence, and pass/fail per mesh.
10. **Repair geometry at the producing rule.** Trace a displaced or misshapen mesh to its transform, unit, frame, primitive-dimension, hierarchy, or export rule; repair and re-export rather than editing individual meshes. If provenance, frame, units, derivation, mapping, or independence cannot be demonstrated, mark unverifiable and block; never substitute the producer's reconstruction or an inline pass.
11. **Package only after a clean, provenanced gate.** If any mesh exceeds tolerance or lacks independence provenance, block and report. Never call clean because a self-referential reconstruction agrees. Preserve the final command, counts, per-mesh results (artifact and reconstruction paths, source scene, frame, units, derivation, tolerance, Chamfer, displacement class, pass/fail), and exit status.

## Constraints

- Every threshold, bound, unit factor, expected value, group order, separation, nullable field, forbidden sentinel, structural requirement, allowed-domain set, geometric tolerance, unit conversion, frame convention, and mesh-to-source mapping comes from the task-derived spec. Read the geometry threshold from `acceptance_tolerance`; never relax a task-stated tolerance to a local default, tool setting, or posthoc value, and never copy hidden verifier constants into the spec or validator. Prohibit task-specific names, benchmark constants, posthoc-oracle values, fixed paths, embedded answers, hidden expected meshes, and hard-coded unit factors; every oracle derives from task-visible source data.
- Supply structural, domain, graph, and encoding contracts per artifact. Never derive pivot fields, aggregation modes, cache contents, allowed labels, graph endpoints, or companion encodings from producer output; never accept a copied category list as the allowed set. A pass in one class does not waive any content, numeric, calibration, or tolerance check.
- File, vertex, face, normal, triangle, and degenerate-face counts establish structural validity only. Matching counts and totals, exact per-mesh vertex or triangle equality, `exact_union=True`, a near-zero triangle delta, link meshes mirroring parts, file presence, an inline `ALL CHECKS PASSED` report, or agreement between checks sharing one implementation (such as a link check comparing a copied part) are structural-only self-consistency; only independent source-scene comparison at the stated tolerance passes `geometry_conformance`.
- Require `provenance.source_scene_path`, `frame`, `units`, `derivation`, and explicit independence evidence. Reject a reconstruction sharing the producer's primitive decomposition, expected coordinates, or transform path, even if labeled independent. Mark geometry unverifiable when provenance or independence is absent, inconsistent with the scene or units, or names the submitted export, manifest, intermediate mesh, producer reconstruction, or its reader/transform path; reject a provenance path resolving to a part or link export or naming a manifest, intermediate, or mesh, even without `source_kind`. Never invent provenance. Reconstruct from source primitive parameters and transforms through a path separate from the exporter; never use exporter output, intermediates, manifest, submitted mesh, or producer functions as baseline. Normalize with the spec's unit, axis, transform, and scene-root versus part-local conventions; mark unverifiable when source, mapping, tolerance, provenance, or normalization is absent or unsupported.
- Supply entry node, terminal exception, node and edge paths, and endpoint fields from the task contract; never hard-code names, sizes, or reachable sets. Multiple inbound paths into a terminal node are legitimate; the terminal exception waives only edge-target existence, not reachability. Mark `graph_structure` unverifiable when the representation lacks nodes, edges, ids, or endpoints.
- Enumerate every named deliverable with one constraint group each, including companions. Never infer companion correctness from existence, byte count, parse success, dimensions, or the primary pass; parse it and compare every declared semantic encoding. Mark it unverifiable when the mapping is absent, a type is unmapped, or attributes are unavailable.
- Contract-declared missing values must be JSON null, never a placeholder or sentinel such as `PO-INVALID`, `N/A`, `TBD`, or the empty string; a non-nullable field must carry a value.
- Preserve failure classes and exit behavior. Remain posthoc-only toward the hidden verifier: never read, embed, or assume hidden expected values; keep invocations portable. Check the complete artifact without sampling, emit violations deterministically in spec then record order, and sort residual output by locator.
- Prohibit expectations from the parse-and-export implementation under test: never take primitives, world transforms, meshes, bounds, or counts from the exporter, manifest, intermediate, or submitted artifact. If no independent recomputation or task-grounded metamorphic invariant applies, mark unverifiable and block.
- Exit nonzero if any violation or unverifiable constraint remains. Never claim clean without a recorded exit status; report an absent expected source, self-referential oracle, unsupported data, or missing hierarchy as unverifiable.

## Verification

Run the clean baseline:

```bash
python3 scripts/preflight.py scripts/fixtures/artifact-clean.json --spec scripts/fixtures/spec-clean.json
python3 scripts/preflight.py scripts/fixtures/artifact-pivot-clean.json --spec scripts/fixtures/spec-pivot-clean.json
python3 scripts/preflight.py scripts/fixtures/graph-clean.json --spec scripts/fixtures/spec-graph.json
```

Each must exit `0` with `status: clean`, zero violations, and zero unverifiable constraints.

Execute the mandatory geometry gate on the box fixtures and the part-and-link regression:

```bash
python3 scripts/preflight.py scripts/fixtures/source-scene-box.json --spec scripts/fixtures/spec-geometry-clean.json
python3 scripts/preflight.py scripts/fixtures/source-scene-box.json --spec scripts/fixtures/spec-geometry-displaced.json

python3 scripts/preflight.py --artifact-root scripts/fixtures/geometry-rig-equivalent --spec scripts/fixtures/spec-rig-clean.json
```

The clean box and equivalent rig exit `0` with passing per-mesh `geometry` entries, including differing vertex counts. The displaced box and rig exit `1`; the rig reports four `geometry_conformance` violations naming `wheel_structure/outer_rim`, `link_wheel_structure/outer_rim`, `support_structure`, and `link_support_structure`, each with Chamfer above `0.01` and `displacement_class: frame_or_placement`. The no-provenance rig exits `1` with an unverifiable entry per mesh. The oracle clean root exits `0` with six passing meshes. The near-miss root exits `1` with `transform_scale`, `transform_translation`, `mis_parented`, `transform_rotation`, `primitive_omission`, and `primitive_duplication` violations naming affected meshes. The self-referential fixture must exit `1` as unverifiable because its expected surface reuses the producer's primitive reconstruction and transform path. The tolerance near-miss must exit `1` at the task-stated `0.01` threshold even though its looser local `0.05` would pass the `0.02` displacement.

Before accepting a geometry report, confirm every expected mesh records `source_scene_path`, `frame`, `units`, `derivation`, and independence evidence for a separate source reader and transform path. Confirm the threshold is the task-derived `acceptance_tolerance`; an absent task tolerance is unverifiable. Confirm no submitted mesh, manifest, intermediate, producer reconstruction, exact-union result, count equality, or inline pass report is the baseline or a pass. Confirm one observed-versus-tolerance entry per named part and link mesh with artifact path, source scene, metric, tolerance, Chamfer, displacement class, and pass or fail. Confirm a nonzero exit on any out-of-tolerance mesh or unverifiable constraint, and that absent independence or tolerance yields `unverifiable` and blocks.

The complete geometry procedure, schema, and worked examples are in `references/mesh-geometry-conformance.md`. Exercise the remaining failure pairs in `references/verification-playbook.md`: equality, range, calibration, recompute, null-sentinel, pivot structure and domain, graph reachability and dangling targets, companions, and the manifest-sourced geometry rejection. Each must exit `1` with the expected invariant class; `scripts/fixtures/artifact-structurally-valid-calibration-fail.json` with `scripts/fixtures/spec-calibration.json` is the clean-shape, failing-separation near-miss. Before declaring an artifact clean, exercise the focused evals on `scripts/fixtures/geometry-oracle-self-referential/` and `scripts/fixtures/geometry-tolerance-near-miss/`; both must exit `1`, the first as unverifiable for self-referential oracle evidence and the second for exceeding the tighter task-stated tolerance. Record the final command, counts, per-mesh results, and exit status.

## Output Format

Print a JSON report to stdout (and `--report PATH` when supplied):

```json
{
  "status": "clean",
  "artifact_path": "path/to/artifact.json",
  "spec_revision": "task-rev-1",
  "counts": {"records": 3, "invariants": 4, "passed": 12, "violations": 0, "unverifiable": 0},
  "invariants": [
    {"id": "eq-total", "class": "equality", "pass_count": 3, "fail_count": 0, "status": "pass"},
    {"id": "encode-po-number", "class": "field_encoding", "pass_count": 3, "fail_count": 0, "status": "pass"}
  ],
  "violations": [],
  "unverifiable": [],
  "geometry": []
}
```

The independent oracle prints a JSON verdict with `status`, `source_scene`, `artifact`, `tolerance`, `oracle.method`, `oracle.transform_path`, per-mesh `expected` and `observed` bounds, centroid, triangle counts, `violations`, and `unverifiable`. Each oracle violation contains `code`, `invariant_class`, `mesh`, `artifact_path`, `primitive`, `field`, `expected`, `observed`, `tolerance`, and `transform` with `translation_delta`, `size_ratio`, expected and observed centroids and bounds, so an omitted or mis-parented primitive is distinguishable from a wrong translation, rotation, or scale.

Each preflight violation contains `invariant_id`, `invariant_class`, `locator`, `field`, `observed`, `expected`, and `diagnosis`, plus `deliverable` for `companion_artifact` or `geometry_conformance`. A companion violation puts the absent path or source node id in `locator` and the encoding attribute in `field`. A `geometry_conformance` violation reports the mesh in `locator`, the metric in `field`, `observed_delta`, tolerance, counts, `deliverable`, `artifact_path`, and `source_scene_path`; the `geometry` array holds one per-mesh entry with `source_geometry`, `evidence`, `max_nearest`, `chamfer`, and `status`. When declared, `export_path_checks` includes one entry per part/link pair with count flags, `triangle_delta`, `status: structural_only`, and a limitation that export-path agreement cannot satisfy `geometry_conformance`. A `field_encoding` violation reports locator, field, observed value, and required rule; `independent_recompute` adds `oracle_path` or `metamorphic_relation` and, when numeric, `observed_delta`. Unverifiable entries name the invariant and reason—self-referential oracle, absent oracle, silent encoding, unknown relation, missing source scene, unsupported primitive, absent mapping, or absent tolerance—and keep `status: violations` with exit `1`. Set `status` to `violations` for any remaining violation or unverifiable constraint and `error` if the spec or artifact cannot be read. Exit `0` only for clean, `1` for violations or unverifiable constraints, and `2` for spec or artifact error.

## Limitations

The preflight is only as complete as the task-derived spec: it cannot discover unexposed constraints, derive absent expected values, or repair producing logic. Null-versus-sentinel checking requires an explicit encoding rule; when silent, mark the field unverifiable. An independent recomputation is only as sound as its assumptions: a second implementation sharing the producer's defective assumption is insufficient, and a metamorphic relation checks only the property it states. When neither path is possible, the constraint remains unverifiable. Passing does not replace the hidden verifier or ground-truth derivation, and structural or sampled checks do not establish conformance. A companion check is only as sound as its mapping; an invisible convention or unparseable format is unverifiable. A geometric check is only as sound as its source reconstruction and frame normalization: surface-sampling and nearest-point metrics are approximations sensitive to tessellation and density, differing vertex counts require a stated metric, and the check cannot establish artistic intent or fidelity beyond the contract. Export-path agreement, including link meshes duplicating part meshes, is structural-only and cannot substitute for the independent source-scene comparison.
